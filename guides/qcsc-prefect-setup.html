QCSC-Prefect auf einem Slurm-Cluster einrichten

Diese Anleitung bereitet den Login-Knoten eines Slurm-Clusters als Workflow-Host von qcsc-prefect vor. Das qcsc-prefect-SQD-Tutorial beginnt mit dem Ergebnis dieser Anleitung.

Nachdem du diese Anleitung abgeschlossen hast, hast du die folgenden Elemente:

ElementWoInhalt
~/venv/qcsc-hostLogin-Knoten, der Workflow-HostPrefect, die qcsc-prefect-Pakete und der Befehl qcsc-qrmi
~/venv/qcsc-nodeRechenknoten, innerhalb von Slurm-JobsDer QRMI-Worker: QRMI mit seinem Befehl task_runner und qcsc-prefect-qiskit
qrmi-runtimePrefectDer Block, der deine IBM Quantum® Instanz und QPU benennt
qrmi_config.jsonLogin-Knoten und RechenknotenDein IBM Cloud® API-Schlüssel, Instanzen und Backends für QRMI

Führe jeden Befehl in einem Terminal auf dem Login-Knoten aus, sofern der Schritt nichts anderes angibt.

Voraussetzungen​

  • Ein Slurm-Cluster mit OpenMPI, PMIx und dem QRMI-SPANK-Plugin, die der Cluster- Administrator installiert. Die folgenden Anleitungen beschreiben diese Komponenten:

    • Quantum resource management interface (QRMI)

    • SPANK-Plugin für QRMI

    • Benutzerhandbuch zum SPANK-Plugin

  • Ein Home-Verzeichnis und ein Arbeitsverzeichnis, die der Login-Knoten und die Rechenknoten unter denselben absoluten Pfaden sehen

  • Ausgehender HTTPS-Zugriff auf GitHub, PyPI, IBM Quantum und Prefect Cloud vom Login- Knoten sowie auf IBM Quantum von den Rechenknoten

  • Ein IBM Quantum Platform Konto mit einem IBM Cloud API-Schlüssel und mindestens einer Instanz

  • Ein Prefect-Cloud-Konto oder ein Prefect-Server, den du selbst hostest

  • Git, C- und C++-Compiler, CMake, BLAS, LAPACK und MPI auf dem Cluster, für die Solver- Builds des Tutorials

hinweis

Die Beispiele verwenden die Slurm-Partition normal und die Rechenknoten c1 und c2. Ersetze sie durch die Namen deines Clusters.

Schritt 1: Am Login-Knoten anmelden​

# Run in a terminal on your computer.
ssh <user>@<login-node>

Schritt 2: uv installieren​

Installiere den Paketmanager uv und prüfe die Installation:

curl -LsSf https://astral.sh/uv/install.sh | sh
source "$HOME/.local/bin/env"
uv --version

Schritt 3: Pfade festlegen und das Arbeitsverzeichnis erstellen​

Diese Anleitung und die Tutorials verwenden zwei Umgebungsvariablen:

VariableBeispielZweck
QCSC_PREFECT$HOME/qcsc-prefectDer qcsc-prefect-Checkout
QCSC_WORK_DIR/shared/work/qcsc-prefectDas Arbeitsverzeichnis der Solver-Jobs und der QRMI-Jobs

Beide Pfade müssen auf Speicher liegen, den die Rechenknoten unter demselben absoluten Pfad sehen. Wenn dein Cluster kein Verzeichnis /shared hat, wähle einen anderen gemeinsamen Pfad.

Setze die Variablen und erstelle das Arbeitsverzeichnis. Setze die Variablen in jeder neuen Shell erneut, bevor du einem Tutorial folgst:

export QCSC_PREFECT="$HOME/qcsc-prefect"
export QCSC_WORK_DIR=/shared/work/qcsc-prefect
mkdir -p "$QCSC_WORK_DIR"

Um die Variablen in jeder neuen Shell automatisch zu setzen, füge sie zu ~/.bashrc hinzu:

# Optional
echo "export QCSC_PREFECT=$QCSC_PREFECT" >> ~/.bashrc
echo "export QCSC_WORK_DIR=$QCSC_WORK_DIR" >> ~/.bashrc

Schritt 4: qcsc-prefect klonen​

Klone das Repository und checke ein Release-Tag aus, zum Beispiel v0.3.1:

git clone https://github.com/qiskit-community/qcsc-prefect.git "$QCSC_PREFECT"
cd "$QCSC_PREFECT"
git checkout v0.3.1

Schritt 5: Die Workflow-Umgebung erstellen​

Erstelle die Workflow-Umgebung mit Python 3.12 und aktiviere sie:

uv venv ~/venv/qcsc-host -p 3.12
source ~/venv/qcsc-host/bin/activate

Installiere die qcsc-prefect-Pakete. Die Option --no-deps behält die exakten Versionsbindungen zwischen den Paketen des Checkouts bei. Das Tutorial installiert den Workflow selbst:

cd "$QCSC_PREFECT"
uv pip install --no-deps \
  -e packages/qcsc-prefect-core -e packages/qcsc-prefect-adapters \
  -e packages/qcsc-prefect-blocks -e packages/qcsc-prefect-executor \
  -e 'packages/qcsc-prefect-qiskit[slurm]'

Prüfe, ob die Befehle verfügbar sind:

which prefect qcsc-qrmi

Aktiviere ~/venv/qcsc-host in jeder neuen Shell auf dem Login-Knoten.

Schritt 6: Bei Prefect anmelden​

Melde dich bei Prefect Cloud an. Wähle Paste an API key, füge einen Prefect-Cloud-API-Schlüssel ein und wähle deinen Workspace:

prefect cloud login

Prüfe die Verbindung. Die Ausgabe zeigt PREFECT_API_URL und deinen Workspace:

prefect config view
Optional: eigenen Prefect-Server verwenden

Überspringe diesen Hinweis, wenn du Prefect Cloud verwendest. Um statt Prefect Cloud deinen eigenen Prefect-Server zu verwenden, folge How to run and access a Prefect server on a Slurm login node und setze die Adresse deines Servers anstelle von <server-host> ein:

# Optional: only for your own Prefect server
prefect config set PREFECT_API_URL=http://<server-host>:4200/api

Schritt 7: Die IBM Quantum-Zugangsdaten speichern​

Führe qcsc-qrmi login nach dem Prefect-Login aus, weil der Befehl den Block qrmi-runtime speichert:

qcsc-qrmi login

Beantworte die Eingabeaufforderungen:

  1. Füge deinen IBM-Cloud-API-Schlüssel ein. Der Schlüssel wird nicht angezeigt.

  2. Drücke die Eingabetaste, um alle Instanzen zu verwenden.

  3. Gib die Nummer der Standardinstanz ein, im folgenden Beispiel 1.

  4. Gib die Nummer oder den Namen des Standard-Backends ein, im folgenden Beispiel 4 (ibm_kingston).

# Output, with your answers after the prompts

Der Befehl gibt außerdem einen Hinweis zu den Rechenknoten und [qrmi]-Zeilen für sqd_blocks.toml aus, die das Beispiel auslässt (...). Du brauchst die [qrmi]-Zeilen nicht, weil der Workflow die Instanz und das Backend aus dem Block qrmi-runtime liest.

Der Befehl qcsc-qrmi hat die folgenden Unterbefehle:

BefehlZweck
qcsc-qrmi loginDen API-Schlüssel, die Instanzen und die Backends speichern und den Block sichern
qcsc-qrmi refreshDie Instanzen und Backends mit dem gespeicherten Schlüssel erneut ermitteln
qcsc-qrmi listDie Instanzen und Backends ohne den Schlüssel ausgeben
qcsc-qrmi checkPrüfen, ob die Instanz des Blocks ihr Backend verwenden kann

Die Datei auf den Rechenknoten installieren​

Das SPANK-Plugin liest qrmi_config.json auf jedem Rechenknoten, und zwar vom Pfad in plugstack.conf, oft /etc/slurm/qrmi_config.json. Bitte deinen Cluster-Administrator, deine ~/.qiskit/qrmi_config.json unter diesem Pfad zu installieren. Installiere sie nach jedem qcsc-qrmi login oder qcsc-qrmi refresh erneut.

Lass Session Mode des Blocks qrmi-runtime auf batch, weil das SPANK-Plugin die QPU im batch mode belegt.

Schritt 8: Die Umgebung für die Rechenknoten erstellen​

Der QRMI-Worker läuft auf einem Rechenknoten in einer eigenen Umgebung. Erstelle sie aus demselben Checkout. Die Option --python hält ~/venv/qcsc-host aktiv:

cd "$QCSC_PREFECT"
uv venv ~/venv/qcsc-node -p 3.12
uv pip install --python ~/venv/qcsc-node/bin/python "qrmi[ibm]"
uv pip install --python ~/venv/qcsc-node/bin/python -e packages/qcsc-prefect-qiskit

Das Paket qrmi[ibm] stellt den Befehl task_runner bereit. Das Tutorial fügt dieser Umgebung den SQD- Kompilierungs-Hook hinzu und verwendet ~/venv/qcsc-node/bin/python als python_executable von sqd_blocks.toml.

Prüfe die gespeicherten Instanzen und Backends. Der Befehl gibt den Schlüssel nie aus:

qcsc-qrmi list
# Output
API key: set
premium-instance (premium, us-east) (default): ibm_boston, ibm_chicago, ibm_fez, ibm_kingston, ibm_marrakesh, ibm_phoenix, ibm_pittsburgh
open-instance (open, us-east): ibm_fez, ibm_kingston, ibm_marrakesh

Prüfe, ob die Standardinstanz das Standard-Backend verwenden kann:

qcsc-qrmi check
# Output
premium-instance (premium, us-east) can use ibm_kingston.

Prüfe, ob Slurm einen Job auf beiden Rechenknoten ausführt, auch mit PMIx:

srun -N2 hostname
srun -N2 --mpi=pmix hostname
# Output of each command
c1
c2

Prüfe die Umgebung für die Rechenknoten und das Arbeitsverzeichnis auf einem Rechenknoten. Der erste Befehl gibt nichts aus, wenn die Importe gelingen:

srun -N1 ~/venv/qcsc-node/bin/python -c "import qrmi, qcsc_prefect.integrations.qiskit.qrmi.worker"
srun -N1 ls ~/venv/qcsc-node/bin/task_runner
srun -N1 ls -ld "$QCSC_WORK_DIR"
